# Acceptance Criteria Generation and Refinement

## Objetivo
Generate clear, measurable, and verifiable acceptance criteria for new features or modifications, ensuring alignment with business rules and user stories.

## Trigger
on new feature development or requirement refinement

## Inputs
- User story or feature request
- Relevant business rules
- Domain definition
- Compliance requirements

## Procedimiento
1. Analyze the provided user story or feature description to understand the core functionality and user expectations.
2. Extract explicit and implicit business rules from the project context (e.g., domain definition, constraints, compliance requirements).
3. Formulate acceptance criteria using a structured format (e.g., Gherkin Given/When/Then) that are specific, measurable, achievable, relevant, and time-bound.
4. Ensure criteria cover both successful paths and expected exception/error handling scenarios.
5. Verify that each criterion is traceable to a business rule or requirement and provides clear evidence expectations for testing.

## Output esperado
A set of well-defined, verifiable acceptance criteria that accurately reflect the feature's requirements and business rules.
